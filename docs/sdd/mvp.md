# Ticket Tracker MVP

## Цель

Создать небольшой трекер задач, на котором можно отрабатывать полный цикл доставки изменений с AI-агентом.

## Основной сценарий

1. Пользователь создаёт тикет с названием, описанием и критериями приёмки.
2. Пользователь задаёт приоритет и статус тикета.
3. В тикете можно указать ссылку на спецификацию, имя ветки и ссылку на pull request.
4. Команда видит тикеты на доске, сгруппированные по статусу.
5. Клиент автоматизации может читать и обновлять тикеты через REST API.

## Поля тикета

- `id` — внутренний числовой идентификатор.
- `key` — отображаемый ключ вида `TT-0001`, формируемый из ID.
- `title` — обязательное название, от 3 до 160 символов.
- `description` — описание задачи.
- `acceptance_criteria` — критерии приёмки.
- `status` — `Backlog`, `In Progress`, `Review` или `Done`.
- `priority` — `Low`, `Medium`, `High` или `Urgent`.
- `spec_ref` — путь или URL спецификации.
- `branch_name` — имя Git-ветки.
- `pull_request_url` — URL pull request.
- `created_at`, `updated_at` — временные отметки.

## Критерии приёмки

1. Главная страница показывает доску с четырьмя колонками статусов.
2. Пользователь может создать тикет через HTML-форму.
3. На доске видны ключ, название, приоритет и статус каждого тикета.
4. Пользователь может открыть тикет, изменить его поля и сохранить изменения.
5. Статус можно изменить с карточки или страницы тикета.
6. Пользователь может добавить к тикету путь спецификации, имя ветки и URL PR.
7. REST API позволяет получить список и отдельный тикет, создать тикет и обновить его.
8. Новые записи хранятся в SQLite и остаются доступны после перезапуска приложения.
9. API описан в автоматически создаваемой OpenAPI-схеме FastAPI.

## Не входит в MVP

- Пользовательские учётные записи и роли.
- Комментарии, вложения и история событий.
- Автоматический запуск AI-агента из тикета.
- GitHub webhooks и автоматическое управление PR.
- Совместная работа нескольких пользователей.
